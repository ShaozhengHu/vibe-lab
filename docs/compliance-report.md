# password-vault 商用密码应用安全性自查报告

| 项 | 内容 |
| --- | --- |
| 应用名称 | password-vault 密码保险箱（个人单机桌面端） |
| 应用定位 | 本地加密存储并解密取回明文密码（凭据）的单机工具 |
| 自查范围 | 密码算法合规性、密钥管理、密码应用有效性（对照 GB/T 39786-2021 与等保 2.0 控制点） |
| 自查日期 | 2026-09-24 |
| 责任说明 | 本报告为项目组自检口径；若应用纳入单位等保/密评范围，以单位安全部门组织的正式评估为准 |

---

## 1. 应用概况

- 形态：Windows 桌面程序（Wails v2 + Go 后端，前端本地 WebView，无网络接口）。
- 数据：用户凭据（账号/密码），按 JR/T 0197-2020 属高敏数据，按 3 级及以上防护要求处理。
- 边界：单机使用，不提供云同步、多用户、浏览器插件；不存在网络传输环节。

## 2. 密码应用范围

| 密码功能 | 应用对象 | 说明 |
| --- | --- | --- |
| 数据机密性 | 库文件、备份文件 | 全库 SM4-GCM 信封加密，凭据明文仅存于解锁后的内存 |
| 数据完整性/真实性 | 库文件、备份文件 | GCM 认证标签（条目级，AAD 绑定）；备份文件 SM3 摘要 |
| 身份鉴别 | 应用解锁 | 主密码 + PBKDF2-HMAC-SM3 派生校验 |
| 安全审计 | 审计日志 | 本地 JSONL 记录关键操作，不含凭据内容 |

明确不涉及：网络传输加密（无网络通信）、电子签名/证书（未启用 SM2，见第 7 节遗留项）。

## 3. 密码算法使用清单

| 算法 | 标准 | 用途 | 关键参数 |
| --- | --- | --- | --- |
| SM3 | GB/T 32905-2016 | PBKDF2 伪随机函数；备份文件完整性摘要 | 输出 256 位 |
| SM4 | GB/T 32907-2016 | 凭据数据加密（GCM 模式）、数据密钥封装 | 128 位密钥；GCM 随机 96 位 nonce；认证标签 128 位 |
| SM2 | GB/T 32918 | （预留）库文件签名 | 未启用，见第 7 节 |

- 未使用 MD5/SHA-1/DES/RSA-1024 等不安全或不合规算法。
- 算法实现来自经过验证的开源库 `emmansun/gmsm`，不自研、不自行组合算法；
  通过 GB/T 32905、GB/T 32907 标准示例测试向量验证（见 `docs/acceptance-checklist.md`）。

## 4. 密钥管理

### 4.1 密钥体系

```
主密码（用户输入，永不上传/落盘）
   │ PBKDF2-HMAC-SM3（随机盐 16B，迭代 60 万次）
   ▼
主密钥 MK（128 位，SM4）── 仅存内存，锁定/退出即清零
   │ SM4-GCM 封装（信封）
   ▼
数据密钥 DK_i（128 位，每条凭据独立、随机生成）
   │ SM4-GCM 加密
   ▼
凭据明文（标题/账号/密码/元数据）
```

### 4.2 密钥生命周期自查

| 环节 | 措施 | 状态 |
| --- | --- | --- |
| 生成 | 盐、条目 ID、数据密钥均由安全随机数生成 | 已实现 |
| 分发/派生 | 主密钥每次解锁现场派生，不存储、不传输 | 已实现 |
| 使用 | 明文仅驻留解锁后的内存，锁定即清零 | 已实现 |
| 存储 | 磁盘仅存密文（库文件、备份文件）；密钥与中间值不留盘 | 已实现 |
| 更换 | 信封加密支持重封装数据密钥；主密码丢失即数据不可恢复，无后门 | 已实现 |
| 销毁 | 内存清零（`clear`）；彻底删除时随机覆盖密文区 | 已实现 |

## 5. 密码应用安全性自查（GB/T 39786-2021）

### 5.1 合规性

- 算法均为国家标准商用密码算法，符合密码法关于商用密码应用的总体要求。
- 密码产品/组件：算法实现为开源库（gmsm），未使用未经检测认证的专有算法；
  正式密评如需"密码产品检测认证"，应结合单位采购策略补充（见第 7 节）。

### 5.2 正确性

- SM3/SM4 国标测试向量通过（GB/T 32905 "abc" 摘要、GB/T 32907 标准示例）。
- 加解密往返、篡改拒绝（改 1 字节即失败）、AAD 绑定（改条目 ID 即失败）均有测试覆盖。
- KDF 一致性：同密码+同盐同密钥、不同盐不同密钥。

### 5.3 有效性（对照等保 2.0 控制点，见第 6 节逐项）

## 6. 等保 2.0 控制点逐项核对

| 控制点 | 要求 | 自查结论 | 证据 |
| --- | --- | --- | --- |
| 身份鉴别 | 鉴别信息复杂度 | 通过 | 主密码 ≥12 位且大写/小写/数字/符号至少三类（`internal/policy`，GUI 与 CLI 共用） |
| 身份鉴别 | 登录失败处理 | 通过 | 连续失败第 3 次起指数退避（2s→4s→…上限 60s），退避期间拒绝任何尝试，成功清零 |
| 身份鉴别 | 超时自动退出 | 通过 | 闲置 5 分钟自动锁定并缩回登录窗口 |
| 访问控制 | 最小化攻击面 | 通过 | 单机、无网络接口、无多用户；内部验证条目不可删除 |
| 数据保密性 | 敏感数据加密存储 | 通过 | 全库 SM4-GCM 信封加密，密钥现场派生不落盘 |
| 数据完整性 | 校验机制 | 通过 | GCM 认证标签 + AAD 绑定；备份 SM3 摘要 |
| 安全审计 | 审计记录 | 通过 | 本地审计日志（JSONL），覆盖创建/解锁/增删/复制/备份/锁定，不含明文内容 |
| 数据备份与恢复 | 备份与恢复 | 通过 | 加密备份（密文副本+完整性校验）；恢复先校验后原子替换，失败不触碰当前库 |
| 剩余信息保护 | 数据清除 | 通过 | 两级删除（回收站/彻底删除覆盖密文）；内存清零；剪贴板 30 秒自动清除 |

## 7. 遗留与可选增强项

| 项 | 说明 | 建议 |
| --- | --- | --- |
| SM2 库文件签名 | 支撑更高等级完整性/真实性要求 | 可选；如纳入等保三级可启用 |
| 审计日志加密存储 | 当前为本地明文 JSONL（不含凭据内容） | 可选；可升级为加密存储 + SM3 摘要链防篡改 |
| 备份文件二次加密钥 | 当前备份为库文件密文副本（本身加密），未再单独加密 | 可选；如备份存放环境不可信时启用 |
| 自动锁定时长可配置 | 当前固定 5 分钟 | 建议接入「设置」页提供配置入口 |
| 密码产品检测认证 | 当前算法实现为开源库 | 正式密评时按单位采购策略评估 |

## 8. 自查结论

1. 本应用在**个人单机自用**范围内，已按"等保二级以上控制点 + GB/T 39786 密码应用要求"
   完成设计、实现与自检；密码算法合规、实现正确、应用有效。
2. 上述结论不替代单位正式等保定级与商用密码应用安全性评估；
   若本工具纳入单位系统范围，应由单位安全部门按 GB/T 22239-2019、
   国密局令第 3 号等要求组织正式评估。
3. 维护要求：涉及密码算法、密钥管理、文件格式的改动，须保持
   `go test ./...` 全绿并同步更新本文档与 `docs/acceptance-checklist.md`。
