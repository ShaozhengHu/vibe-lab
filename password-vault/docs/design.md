# password-vault 设计方案

## 1. 项目定位

个人单机、桌面端、可加密存储并解密取回明文密码的凭据保险箱。
设计上对齐金融行业等保 2.0 关键控制点与密码法/商用密码合规要求，加密体系全部采用国密算法。

明确不做：云同步、多用户、浏览器插件（保持单机边界，缩小攻击面）。

## 2. 合规依据

| 依据 | 关键要求 | 对应设计 |
| --- | --- | --- |
| 等保 2.0（GB/T 22239-2019） | 身份鉴别（标识唯一、鉴别信息复杂度、登录失败处理、超时自动退出）、数据保密性、数据完整性、安全审计、数据备份与恢复、剩余信息保护 | 本方案逐项映射，见第 6 节 |
| 密码法（2020-01-01 施行） | 商用密码产品依法检测认证；关键信息基础设施应使用商用密码保护并开展商用密码应用安全性评估 | 只使用合规商用密码算法，不自研算法 |
| 商用密码管理条例（国务院令第 760 号） | 关键信息基础设施"同步规划、同步建设、同步运行"商用密码保障系统，每年至少一次密评 | 密码应用方案文档化、可审计 |
| 商用密码应用安全性评估管理办法（国密局令第 3 号） | 密评 = 合规性、正确性、有效性评估 | 自检口径：算法合规、实现正确、应用有效 |
| GB/T 39786-2021《信息系统密码应用基本要求》 | 密码算法须符合法律法规和国标/行标；密码产品应达相应安全等级 | 算法选型与测试向量验证 |
| 国密算法标准 | SM2（GB/T 32918）、SM3（GB/T 32905）、SM4（GB/T 32907）；MD5/DES/SHA-1/RSA-1024 等属不安全选项 | 只使用 SM2/SM3/SM4 |
| 金融数据安全分级（JR/T 0197-2020） | 数据安全级别 1-5 级；凭据/口令类属高敏数据 | 按高敏数据处理 |

合规边界：个人单机自用工具通常不强制触发等保定级与强制密评。
本方案以"等保二级以上控制点 + GB/T 39786 密码应用要求"为自检基线；
若未来纳入单位系统（如等保三级），可直接支撑密评。是否纳入单位定级/密评范围，需与单位安全部门确认。

## 3. 威胁模型

| 威胁 | 防护 |
| --- | --- |
| 磁盘/备份文件被拷贝 | 全库 SM4-GCM 密文，密钥由主密码派生，无主密码不可读 |
| 暴力破解主密码 | 高迭代 PBKDF2 + 随机盐 + 连续失败锁定/退避 |
| 恶意软件读内存/剪贴板 | 明文仅驻内存，锁屏/退出清零，剪贴板定时清除 |
| 文件被篡改/替换 | GCM 认证标签校验，失败即拒绝打开；可选 SM2 签名 |
| 删除不彻底 | 删除时随机数据覆盖密文区（剩余信息保护） |
| 程序被静态反编译/逆向分析 | 密钥由主密码运行时派生、从不落盘，二进制中不含密钥；算法为标准公开算法（SM2/SM3/SM4），逻辑泄露不构成数据泄露；因此不依赖代码混淆，保持可维护与可审计 |

## 4. 加密与密钥体系

1. 密钥派生：主密码 + 随机盐（16 字节）→ PBKDF2-HMAC-SM3，迭代 ≥60 万次
   （按硬件性能上调）→ 输出 32 字节，取前 16 字节为 SM4 主密钥 MK（128 位）。
   盐与迭代参数写入文件头。
2. 信封加密：每条凭据随机生成独立数据密钥 DK_i（128 位）；
   凭据明文用 DK_i + SM4-GCM 加密（每条独立随机 IV，AAD 绑定条目元数据防替换）；
   DK_i 由 MK 用 SM4-GCM 封装后随条目存储。
   更换主密码只需重封装 DK_i，无需重加密全部凭据；支持按条目轮换密钥。
3. 完整性与真实性：SM4-GCM 认证标签同时保证机密性与完整性；可选 SM2 对库文件签名。
4. 密钥生命周期：MK 从不落盘，仅存内存、锁定/退出即清零；
   不提供"找回主密码/后门"——主密码丢失即数据不可恢复（合规安全设计的必然结果，UI 需明确提示）。

## 5. 库文件与备份格式（实现）

### 5.1 库文件（`vault.vault`，全部小端序）

```
文件头（26B）: 魔数"PVLT"(4B) | 格式版本 uint16(2B) | KDF 盐(16B) | KDF 迭代次数 uint32(4B)
条目区:       条目数 uint32(4B) | 条目 × N
条目体:       条目 ID(16B) | 凭据密文(变长) | nonce1(12B) | tag1(16B) | 数据密钥密文(16B) | nonce2(12B) | tag2(16B)
```

- 条目明文为 JSON（标题/账号/密码/地址/端口/备注/创建时间/内部标记/回收站标记）。
  `address`/`port`/`note` 为可选补充字段（如服务器 IP、端口、备注），采用 `omitempty`：
  旧库条目无这些字段，读取默认为空，**零格式破坏、无需升级版本**；新增/编辑由
  `AddFull`/`Update` 写入（`Add` 三参形式保持兼容，扩展字段留空）。
  `deleted` 字段同样采用 `omitempty`：旧库条目无该字段，读取默认"未删除"，
  因此回收站功能**零格式破坏、无需升级版本**。
- 版本化设计：文件头记录算法与迭代参数，未来可升级强度并保持兼容。

### 5.2 备份文件（`password-vault-backup-<时间>.vault`）

```
备份信封（54B）: 魔数"PVLB"(4B) | 版本 uint16(2B) | 创建时间 int64(8B) | 数据长度 int64(8B) | SM3 摘要(32B)
数据区:         库文件密文（整体副本，不含任何明文）
```

- 恢复时依次校验：魔数 → 版本 → 长度一致性 → SM3 摘要 → 库格式完整解析，
  任一步失败即中止且不触碰当前库；全部通过才原子替换并强制重新解锁。

### 5.3 审计日志（`audit.log`，与库文件同目录）

- JSONL 逐条追加，记录动作与结果（创建/解锁含失败/新增/复制/移入回收站/
  恢复/彻底删除/备份/恢复备份/锁定）；**不记录密码明文与凭据内容**。

## 6. 等保控制点映射（落地事实）

| 控制点 | 等保要求 | 落地措施 | 实现位置 |
| --- | --- | --- | --- |
| 身份鉴别 | 标识唯一、复杂度、失败处理、超时退出 | 主密码 ≥12 位且四类字符至少三类；连续失败第 3 次起 2 秒指数退避、上限 60 秒；闲置 5 分钟自动锁定 | `internal/policy`、`internal/gui/service.go`、前端自动锁定 |
| 数据保密性 | 敏感数据加密存储 | 全库 SM4-GCM 信封加密，密钥由主密码现场派生、从不落盘 | `internal/crypto`、`internal/storage` |
| 数据完整性 | 校验机制 | GCM 认证标签（条目级 AAD）；备份文件 SM3 摘要 | `internal/crypto`、`internal/storage/backup.go` |
| 安全审计 | 审计记录 | 本地 JSONL 审计日志，记录关键操作与结果，不含内容 | `internal/gui/audit.go` |
| 数据备份与恢复 | 备份与恢复 | 加密备份（密文副本 + SM3 完整性校验），恢复先校验后原子替换 | `internal/storage/backup.go` |
| 剩余信息保护 | 数据清除 | 两级删除：回收站软删除可恢复，彻底删除时随机覆盖密文再原子重写；内存密钥清零；剪贴板 30 秒自动清除 | `internal/storage/cover.go`、`internal/gui/service.go` |

## 7. 技术选型

- 语言：Go（国密库 gmsm 成熟、维护成本低、单文件分发）。
- GUI（第 3 阶段）：Wails（系统 WebView + Go 后端）。
- 加密库：emmansun/gmsm（SM2/SM3/SM4，含 SM4-GCM），不自研算法。
- 结构：加密核心与 UI 分层；加密模块独立成库并做单元测试。
