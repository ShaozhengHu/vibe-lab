02
加密与密钥体系（核心原理）
一条链完成"密码 → 密钥 → 密文"；信封加密让每条凭据独立密钥、改主密码不重加密数据。
输入主密码用户记忆，永不落盘、不上传
→
密钥派生 KDFPBKDF2-HMAC-SM3随机盐 16B · 迭代 60 万次 · 抗暴力破解
→
主密钥 MKSM4 · 128 位仅存内存，锁定 / 退出即清零
→
信封封装（每条独立）随机数据密钥 DKMK 用 SM4-GCM 封装 DK
→
凭据加密SM4-GCM随机 nonce 12B · 认证标签 16B · AAD=条目 ID 防替换
→
磁盘全量密文库文件 / 备份均为密文，篡改即校验失败
为什么这样做：① 主密码错误、密文被改、条目被替换都逃不过 GCM 认证，程序统一拒绝打开；② 修改主密码只需用新 MK 重新封装各 DK，凭据密文不动，秒级完成；③ 主密码丢失即数据不可恢复——这是合规安全设计的必然结果，无后门。
03
关键业务流
五条核心链路，从用户操作到磁盘落盘。蓝=关键动作，红=危险/确认动作，绿=恢复/成功。
创建保险箱设置主密码（≥12 位·三类字符）→生成随机盐→派生主密钥 MK→写入空库文件（PVLT 头）→解锁进入主界面
解锁输入主密码→按库头盐/迭代派生 MK→解封 DK 并解密条目（GCM 校验）→载入凭据列表失败：指数退避 2s→60s
新增 / 编辑凭据填 标题/账号/密码/地址/端口/备注→随机 DK + SM4-GCM 加密（AAD=条目ID）→追加/替换条目→原子写回库文件
删除（两级）删除 = 移入回收站（软删，可恢复）→彻底删除（二次确认）→随机数据覆盖旧密文区→原子重写（剩余信息保护）
备份 / 恢复备份：库整体密文副本→封装 PVLB 信封 + SM3 摘要→恢复：先验魔数/版本/摘要/库格式→全部通过才原子替换→任一失败即中止，不触碰当前库
修改主密码验旧密码→新盐 + 派生新 MK→用新 MK 重新封装各条 DK→原子写回（凭据密文不动）→完成，旧密钥清零
锁定 / 自动锁定手动锁定 或 闲置 5 分钟→清空内存密钥与明文→窗口缩回登录小框→剪贴板密码 30 秒自动清空
04
等保 2.0 / 密码法合规映射
按 GB/T 22239-2019 与 GB/T 39786-2021 控制点逐项落地的实现位置（完整口径见 docs/compliance-report.md）。
控制点落地措施实现位置
身份鉴别（复杂度）主密码 ≥12 位，且大写/小写/数字/符号至少三类；GUI 与 CLI 共用同一策略internal/policy · frontend
身份鉴别（失败处理）连续失败第 3 次起指数退避，上限 60 秒；退避期间拒绝一切尝试，成功即清零internal/gui/service.go
身份鉴别（超时退出）闲置 5 分钟自动锁定并缩回登录窗口frontend/js/app.js
数据保密性全库 SM4-GCM 信封加密，密钥由主密码现场派生、从不落盘internal/crypto
数据完整性GCM 认证标签（条目级 AAD 绑定）；备份文件 SM3 摘要校验internal/crypto · storage/backup.go
安全审计本地 JSONL 审计日志：解锁/增删/复制/备份/锁定等，不含密码明文与凭据内容internal/gui/audit.go
备份与恢复加密备份（密文副本 + 完整性校验）；恢复先校验后原子替换，失败不触碰当前库internal/storage/backup.go
剩余信息保护两级删除，彻底删除时随机覆盖旧密文再原子重写；内存密钥清零；剪贴板 30 秒自动清除storage/cover.go · gui/service.go
密码法 / 密评仅使用合规商用密码算法 SM3/SM4（不自研），算法实现经国标测试向量验证（GB/T 32905/32907）internal/crypto + 测试
